# Make

1. Produce the agreed artifact while preserving unrelated work and intended behavior.
2. For production behavior changes, load and follow [the TDD skill](../tdd/SKILL.md) before changing production code.
3. For documentation or design work, do not claim TDD execution.
4. Keep generation and business logic in functions where practical; keep UI components focused on presentation.
5. Hand off the change, verification evidence, blockers and limitations. Do not initiate commits.
