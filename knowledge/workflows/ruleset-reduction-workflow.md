# Ruleset reduction

## Goal

Create a substantially smaller new repository practice-set version containing only agreed essentials and important practices. Unlike version 4's shorter entry point, this review may explicitly retire or make obligations optional; it must not merely move the same mandatory reading elsewhere.

## Scope

- Review repository guidance, detailed practices, current and retired principle entries, practice/process documents, both custom agents and all five repository skills.
- Review each item with the user; consolidate duplicates rather than counting repeated wording as separate decisions.
- User/profile/plugin customizations may be identified as dependencies, but changing them requires separate scope approval. Platform/runtime requirements are outside the repository practice-set scope and cannot be removed by this review.
- Preserve previous versions and source history. Current rules remain active until the replacement is explicitly approved.

## Steps

1. Establish a complete, deduplicated source inventory and baseline size. Distinguish active obligations, examples, historical entries and supporting references.
2. Review each item with the user using MoSCoW and record decisions in the ledger. Unreviewed items remain undecided; do not infer within-category order from review order.
3. Complete the source/preservation audit and agree within-category ordering later.
4. Draft the reduced set within the agreed always-on size budget, including mandatory references, without hiding obligations in archives.
5. Validate realistic tasks: coding/test repair, a same-task refinement, metrics upkeep and a requested commit.
6. Verify coverage of the inventory, links, loading scope and removed obligations. Obtain approval before replacing current guidance.
7. Follow versioning policy: commit actual practice changes only on request, then register the next sequential version pinned to that committed content in a follow-up commit. Do not invent activation dates or a source commit.
