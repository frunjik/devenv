# Evaluate

1. Compare the result directly with agreed success conditions; tests and coverage are not substitutes for the requested outcome.
2. Use relevant runtime and UI evidence when necessary, including interactions and viewport sizes.
3. Review practice compliance separately from passing tests, coverage and builds.
4. For opted-in tracking, retain observed metrics and unknowns without inventing effort or user benefits.
5. Report failures and unavailable checks explicitly; decide whether to finish, revise or continue.
6. Being ready does not authorize a commit; the guide handles commits only on explicit request.
